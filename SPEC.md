# OpenVoiceDesktop Handy-Style UX Spec

§G
G1: Build OpenVoiceDesktop into Handy-like desktop dictation app: fast visible feedback, polished settings, tray, overlay, configurable behavior.
G2: Keep primary transcription path remote OpenAI-compatible ASR: record audio, send `{base_url}/v1/audio/transcriptions`, paste returned text.
G3: Use Handy as UX/reference code, not fork base. Handy ref: `https://github.com/cjpais/Handy`, commit `1c4f21acd2bab81f75a0cd7556cd3bb7399ffd9a`, release `v0.9.1`.
G4: Settings is production control surface, not schema preview: every visible value/action must describe and control real runtime behavior.
G5: Treat text returned by remote ASR as final semantic transcript; desktop may apply presentation-only output behavior, never linguistic correction, filler removal, post-processing, or translation.
G6: Offer optional post-paste selection so user can immediately replace or delete unwanted dictated text.
G7: Keep frequent dictation interactions unobtrusive: vocabulary hints discoverable, Save visibly acknowledged, recording overlay tiny, and default paste path near-immediate.

§C
C1: No local offline model manager in v1. Do not add `transcribe-cpp`, `transcribe-rs`, ONNX, Vulkan, Metal, model downloads, or model unload controls unless later product decision changes.
C2: Remote ASR endpoint config stays first-class: `base_url`, `model`, token source, language, prompt, timeout/retry.
C3: Use Tauri 2 desktop shell with bundled frontend assets and system webview (WebView2 on Windows); core ASR/record/paste stays testable as Rust library. Do not open settings in external browser or expose production settings through localhost HTTP.
C4: GNOME Wayland and Windows 10/11 remain target platforms. macOS support can be designed but not required by current README.
C5: Secrets never logged. Token UI must store through platform secret store when possible; config plaintext token remains fallback only.
C6: Handy code references use `H:<path>` relative to Handy repo at pinned commit. New agent should clone with: `git clone https://github.com/cjpais/Handy /tmp/Handy-review && git -C /tmp/Handy-review checkout 1c4f21acd2bab81f75a0cd7556cd3bb7399ffd9a`.
C7: Preserve low dependency surface unless feature requires app shell. Avoid importing Handy local inference dependencies.
C8: UX must feel immediate even when remote ASR latency exists: state changes visible before network call starts.
C9: Prefer desktop webview window over platform-native widget toolkit. True WinUI widgets are out of scope unless webview accessibility or integration fails.
C10: No visible enabled control/action may be a placeholder. Unsupported optional features stay hidden or visibly disabled with exact availability reason.
C11: Settings save must either apply atomically to running daemon or explicitly mark field restart-required before save; silent stale runtime forbidden.
C12: ASR service owns vocabulary biasing, transcript cleanup, filler handling, correction, and translation. Desktop sends standard request context (`language`, `prompt`) and does not load or call a separate language model.
C13: Post-paste selection defaults off, never changes transcript text or clipboard contents, and must not claim success when target app/tool cannot select exact inserted span.
C14: Vocabulary hints use standard multipart ASR `prompt`; they are service request context, not desktop-side correction or custom-word replacement.
C15: Clipboard safety delays must have measured platform need, clear units/purpose, conservative bounds, and zero effect on direct-type/copy-only paths where irrelevant.

§R
R1: Tauri 2 Windows uses Microsoft Edge WebView2; Windows 10/11 normally provide runtime. `https://v2.tauri.app/start/prerequisites/`; `https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution`
R2: Tauri 2 global-shortcut plugin supports Windows/Linux registration plus pressed/released events, fitting toggle and push-to-talk. `https://v2.tauri.app/plugin/global-shortcut/`
R3: Tauri 2 official desktop surfaces cover system tray, autostart, logging, opener, single-instance, updater, window state. `https://v2.tauri.app/plugin/`
R4: Tauri 2 documents Linux→Windows NSIS cross-compilation with `nsis`, LLVM/LLD/Clang, `cargo-xwin`, and `x86_64-pc-windows-msvc`; output lives under the target-specific `release/bundle/nsis` directory. Cross-build is less tested than native Windows and does not replace Windows runtime smoke. `https://v2.tauri.app/distribute/windows-installer/`

§V
V1: Remote ASR invariant: every transcription request goes to `{base_url.trim_end_matches('/')}/v1/audio/transcriptions`; no local model inference path used by default.
V2: Secrets invariant: bearer tokens/API keys redacted from logs, UI debug output, error messages, and history.
V3: Feedback invariant: user receives visible state within 100 ms of accepted toggle/cancel command, before audio write or network call.
V4: Busy invariant: second toggle during writing/transcribing/inserting does not start nested recording; returns busy or cancel-capable state.
V5: Cancel invariant: pressing configured cancel shortcut (default `Escape`) during recording stops and discards capture without ASR upload or paste; during writing/transcribing/inserting it suppresses pending network/paste result; final state becomes idle and overlay hides. Cancel while idle is safe no-op.
V6: Paste invariant: paste failure never loses transcript; text remains available through clipboard/history/error UI.
V7: Clipboard invariant: when restore enabled, original clipboard is restored after paste delay; when disabled/copy-only, user-selected behavior respected.
V8: Config invariant: settings schema migrations preserve existing TOML values and never overwrite user token/source silently.
V9: Platform invariant: Linux Wayland path prefers `wtype`/`wl-copy` when available; X11 path supports `xdotool`; Windows path uses native clipboard and `SendInput`.
V10: History invariant: completed transcript saved with timestamp, text, status, endpoint/model metadata, and optional audio file only according to retention policy.
V11: UI invariant: all settings visible in UI map to persisted config and can be changed without editing TOML, except explicit advanced raw config path.
V12: Test invariant: every new platform-independent feature has unit tests; platform behavior has adapter boundary tests or documented manual verification.
V13: Handy-reference invariant: every Handy-inspired feature task cites `H:<path>` so new agent can inspect upstream behavior.
V14: Visible settings invariant: Settings UI must be user-invokable from the app surface (`openvoice-desktop settings` and tray Settings where tray exists), render persisted config fields, and save edits without hand-editing TOML.
V15: Honest-control invariant: every visible enabled settings control/action has automated proof of current-value render, validated persistence/action, and runtime consumption; otherwise hidden or disabled with reason.
V16: Native-window invariant: tray Settings focuses one desktop application window; no external browser, localhost listener, duplicate settings process, or duplicate daemon.
V17: Live-config invariant: successful Save reports per-field applied/restart-required status; runtime-effective fields update daemon before success response; invalid update preserves prior config/runtime.
V18: Shortcut invariant: displayed toggle/push-to-talk/cancel shortcuts equal registered global shortcuts; defaults are toggle `Ctrl+Space` and cancel `Escape`; cancel fires on key press only; conflicts return visible error without losing prior registration.
V19: Device invariant: microphone/output selectors enumerate current devices, identify system default, persist stable selection, use selected device, and fall back visibly when device disappears.
V20: Audio-settings invariant: ASR encoding displays effective defaults (`16000` Hz, mono) and validates supported values; feedback device/volume/theme and mute/always-on controls affect real audio lifecycle or remain unavailable.
V21: Action invariant: every tray/settings action performs named operation and reports success/sanitized failure; no placeholder redirects such as `Action available in settings UI`.
V22: Completeness invariant: CI maintains explicit inventory of every config field and settings action; adding visible field/action without render, validation, persistence, runtime/action, and test fails.
V23: Desktop-shell invariant: `cargo test --features desktop-shell` passes on Linux and Windows; every Tauri configured/generated bundle asset exists.
V24: Text-ownership invariant: desktop sends audio plus configured `language`/`prompt`, then preserves returned transcript text except explicit presentation operations such as one trailing space; no fuzzy replacement, filler removal, translation, or second-LLM call.
V25: Post-paste selection invariant: when `output.select_pasted_text=true`, successful clipboard-paste or direct-type output leaves exact inserted transcript span selected in target app, including whitespace, punctuation, Unicode, and multiline text. Selection runs after insertion and before clipboard restore. Disabled setting changes nothing. Copy-only, failed insertion, external-script output, unsupported tool/app, and `auto_submit` incompatibility produce validated unavailability or sanitized visible failure; never select unrelated pre-existing text or report inserted success falsely.
V26: Settings-save invariant: successful Save keeps settings window open and focused, preserves active section, and displays persistent applied/restart-required confirmation; failure keeps panel open with sanitized error.
V27: Built-in-feedback invariant: default start/stop/error feedback requires no user-provided files; `audio.audio_feedback` alone enables built-in theme on fresh config, while custom paths are required only for custom theme.
V28: Recording-output invariant: recording output mode is exactly `unchanged`, `reduced`, or `muted`; reduced mode applies validated `audio.recording_output_volume` in `0.0..=1.0`, and muted mode suppresses output.
V29: Audio-restore invariant: stop, cancel, recorder/ASR/paste error, reload rejection, and shutdown restore exact pre-recording output mute and volume state; failed output adjustment cannot leave partial changed state.
V30: Windows-install invariant: release provides versioned per-user NSIS setup executable requiring no Git, Rust, source checkout, or administrator rights; interactive install opens first-run setup, `/S` installs silently, upgrade/uninstall preserve config and credentials, and uninstall removes executable, shortcuts, and autostart registration.
V31: Windows-device-inventory invariant: one settings process enumerates live CPAL/WASAPI input/output devices at most once and reuses that inventory for repeated document loads; runtime audio paths remain live.
V32: Installer-smoke invariant: successful Windows install/reinstall/uninstall smoke exits `0`; expected negative probes such as absent scheduled-task checks never leak nonzero native exit status.
V33: Windows-GUI invariant: release `desktop-shell` executable uses Windows GUI subsystem, so double-click/Start menu launch opens settings or tray app without console window; debug builds retain console diagnostics.
V34: Settings-responsiveness invariant: Save never blocks Tauri UI thread on daemon IPC or OS lifecycle commands; daemon reload has bounded timeout, window remains responsive/open, and atomic rollback semantics remain intact.
V35: Installer-progress invariant: Windows install, upgrade, and uninstall never wait indefinitely for app shutdown or lifecycle commands; graceful stop is time-bounded and force-stop fallback runs before binary replacement.
V36: ASR-prompt invariant: ASR Endpoint shows persisted multiline `Prompt / vocabulary hints`; Save preserves Unicode/newlines, empty input serializes as absent, and every transcription sends non-empty value as multipart `prompt` without desktop text transformation.
V37: Save-feedback invariant: pointer or keyboard activation changes Save button within one rendered frame to disabled busy state with spinner and `Saving…`; exactly one request runs; success shows visible `Saved` confirmation and changed-field disposition; failure shows visible sanitized error and restores enabled button. All states announced through accessible live status.
V38: Tiny-overlay invariant: default compact recording overlay is at most `260×52` logical pixels including shadow, uses one short state label, reduced waveform, and icon-sized accessible cancel action; it never steals focus. Expanded style remains optional. Scaling at 100–200% DPI preserves readable text and screen bounds.
V39: Paste-latency invariant: diagnostics measure ASR-response→clipboard-write, clipboard-write→paste-input, and paste-input→clipboard-restore separately. Windows default sends paste input within `100 ms` of ASR response on local idle system. Restore cleanup never delays visible inserted-state feedback. Configured delays run only on applicable clipboard-paste paths.
V40: Delay-UX invariant: UI names `paste_delay_ms` as pre-paste settling delay and `restore_delay_ms` as post-paste clipboard restoration delay, shows milliseconds and purpose, hides both under Advanced, validates `0..=2000`, and identifies platform defaults. Pre-paste default is `0` unless compatibility tests prove nonzero required; restore delay prevents asynchronous target apps reading restored old clipboard.
V41: Daemon-recovery invariant: valid Settings Save with no reachable daemon starts one hidden, waits at most `5 s` for readiness, and succeeds using saved config; duplicate daemon remains forbidden. Reachable daemon rejection or failed bounded startup preserves prior config/runtime and returns visible sanitized error.
V42: Deferred-save invariant: valid Settings Save when no daemon runtime exists—including incomplete onboarding—persists config without rollback, marks otherwise-live changed fields `restart-required` with reason, and applies them when daemon next starts. Only a reachable daemon's explicit rejection or OS lifecycle failure rejects Save.
V43: Settings-reopen invariant: closing Settings hides rather than destroys its webview while shell/overlay process remains; tray Settings or `settings` command subsequently shows, unminimizes, and focuses same window without duplicate shell or daemon.
V44: Settings-render invariant: every declared control kind renders without JavaScript exception; textarea controls accept multiline value without assigning input-only properties, and one control failure never truncates later controls/actions silently.
V45: Runtime-language invariant: language changes only while idle or recording, updates status/overlay immediately, and remains selected for later recordings in current daemon session. Stop snapshots selected language for one ASR request without splitting audio; `auto` omits multipart `language`. Writing/uploading/inserting rejects changes. Shortcut and overlay invoke same action.
V46: Overlay-cursor invariant: hovering Windows native or Tauri recording overlay always shows normal arrow over non-actions and pointer over clickable language/cancel actions; missing/inherited wait cursor forbidden.
V47: CI-action-runtime invariant: repository-owned workflows use supported GitHub JavaScript action majors targeting Node 24; explicit Node 20 action majors forbidden.
V48: Windows-autostart invariant: autostart uses idempotent current-user registration requiring no administrator rights or password; runtime and installers use one `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` value with exact quoted daemon command, remove legacy task/shortcut registrations, and surface sanitized OS rejection.
V49: Local-release invariant: the repository defines no CI workflows and a push starts no remote build. One local script runs the test suite, bundles both platform artifacts on the Ubuntu host, verifies and checksums them, refuses to publish from a dirty tree or an unpushed commit, and uploads exactly those files to the tagged GitHub release. Each platform is independently releasable. Regression tests over repository text must pass under both LF and CRLF checkouts.
V50: Selection-suffix invariant: when post-paste selection and trailing-space presentation are both enabled, selection covers dictated text but leaves exactly one presentation-only trailing ASCII space unselected. Windows waits for paste processing before caret movement; selection input starts from pasted-text end and never consumes preceding text. Unsupported targets preserve inserted text and suffix and report sanitized failure.
V51: Linux-install invariant: release provides versioned `amd64` Debian package requiring no Git, Rust, or source checkout; install/upgrade preserve config, history, logs, and Secret Service token; removal deletes binary, packaged systemd user unit, and desktop entry while keeping user data. Package declares webview/ALSA/`wl-clipboard` runtime dependencies, ships the user unit so the autostart toggle's `systemctl --user enable` resolves, and its desktop entry opens the settings window. Local build verifies payload without root; install/upgrade/remove smoke runs on Ubuntu CI before release upload. Neither platform's artifact job gates the other's: both depend on tests only and tolerate losing the release-creation race.
V52: Linux-tray invariant: while the resident daemon runs with `app.show_tray_icon` enabled it owns exactly one StatusNotifierItem whose icon is rasterized in-process, so it appears without any installed theme asset. The icon distinguishes idle, recording, transcribing, and error, and error never reuses the recording appearance. Left click toggles recording; the context menu renders `TrayMenuModel` verbatim and its Cancel/Quit entries act on the live controller. A session with no StatusNotifier host logs the reason and leaves dictation working. Every daemon exit path retracts the item, and toggling the setting at runtime adds or removes it without restarting the daemon.
V53: Linux-hotkey invariant: the compositor owns global hotkeys, so `behavior.shortcut` and `behavior.language_shortcut` only take effect once written into GNOME custom keybindings. The daemon reconciles them at startup and on every accepted config reload, reusing one stable dconf path per action so a rebind edits its entry instead of adding one, preserving custom keybindings owned by other applications, and registering commands that launch the running executable. A conflicting accelerator owned by another entry is reported, never silently overwritten. A failed registration is logged and never rolls back an otherwise valid Save.
V54: Linux-overlay invariant: the recording overlay lives in the Tauri shell, so the daemon starts one shell with the Settings window hidden whenever `app.show_overlay` is set, stops it on every exit path, and reconciles it on config reload. Single-instance activation from that hidden relaunch must not show the Settings window, while a user launch must. `settings` runs outside any tokio runtime because the Linux single-instance plugin opens a blocking D-Bus connection. On a Wayland session with Xwayland reachable the shell requests the X11 backend, since the Wayland compositor ignores client window placement and the overlay must sit centered and above other windows; an explicit `GDK_BACKEND` wins.
V55: Endpoint-check invariant: the endpoint test uploads a silent clip and never opens the microphone, so every surface presenting its result labels it as a connection check and never renders the latency or the model's reply to silence as a transcript.
V56: Test-hermeticity invariant: the suite gives the same result on a machine that already holds a real ASR token and on a fresh checkout. Machine-owned token sources - `OPENVOICE_DESKTOP_TOKEN` and the OS secret store - outrank config at runtime and must be switchable off, and every test asserting token resolution, token source, or onboarding token gating turns them off before building its fixture.
V57: Paste-tool invariant: `output.typing_tool` selects the tool for the paste as well as for typing, submitting, and selection. Auto-detection tries each candidate and treats a non-zero exit as a failure, so a tool the compositor cannot support - `wtype` under Mutter, which lacks `zwp_virtual_keyboard_v1` - falls through instead of silently dropping the transcript.
V58: Hotkey-claim invariant: the daemon reports every other desktop component that claims a registered accelerator, matching each component's own spelling, and never edits settings it does not own.
